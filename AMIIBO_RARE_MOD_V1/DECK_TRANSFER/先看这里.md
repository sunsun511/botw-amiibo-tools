# 珍品 amiibo 测试版 V1

这是《旷野之息》Switch 版的掉落 MOD 候选版。已完成文件结构与安装恢复测试，**尚未在你的 Steam Deck 游戏内验证**。

## 现在先用哪一个

先用 `01_core`：奖励只包含黄昏弓、鬼神大剑、大鼓隆之剑、鬼神面具、鬼神服、鬼神靴。

配置中的基础权重依次为 25、20、15、14、13、13。游戏已有物品筛选可能改变最终概率；不能将配置权重当成实际观测掉率。已拿过的武器仍可能重复。鬼神服装利用游戏原有的集齐前筛选，不能保证集齐后永久去重。

候选表中已移除普通材料、食材、箭矢、普通武器。每次扫描目标为一个奖励（马具可能成对），不额外下普通物资雨。三个游戏进度阶段都写入相同珍品池，即本 MOD 有意解除该入口的奖励进度门槛；amiibo 能力、每日使用限制与召唤地点条件仍保持原样。

## 必须分清两种文件

- `amiibo/rare_hub_archer.bin`：在游戏等待 amiibo 时，通过 Load Amiibo 加载。
- `profiles` 与 `install.py`：用于修改游戏奖励，**不能在 Load Amiibo 窗口加载**。

只加载 `.bin`、没有安装 MOD，仍然会出原本的弓箭林克奖励。该 bin 与以前的 `link_archer_plain_test.bin` 使用同一身份和 UID；换文件名不会重置每日限制。

## 安装到 Deck

1. 把整个 `DECK_TRANSFER` 文件夹传到 Deck，例如 `/home/deck/Documents/DECK_TRANSFER`。不需要传父目录的工具库、测试文件。
2. 完全退出游戏与模拟器。
3. 在模拟器游戏列表中右键《旷野之息》，打开该游戏的 MOD 数据位置，找到**现有女性角色 MOD**的 `romfs`。它应已有 `Actor` 和 `System/Resource/ResourceSizeTable.product.srsizetable`。
4. 打开 Konsole，运行下面的命令；把引号中的 `你的实际路径/romfs` 换成刚才找到的路径。

```sh
python3 /home/deck/Documents/DECK_TRANSFER/install.py --romfs "你的实际路径/romfs" --profile 01_core
```

上面只预览，不写入。确认输出指向正确 MOD 后运行：

```sh
python3 /home/deck/Documents/DECK_TRANSFER/install.py --romfs "你的实际路径/romfs" --profile 01_core --apply
```

安装器只写入两个目标文件：

- `Actor/Pack/Item_Amiibo_DropTable_008.sbactorpack`
- `System/Resource/ResourceSizeTable.product.srsizetable`

它会把资源大小表的其他条目完整保留；原文件备份在 `romfs` 同级的 `.amiibo_rare_v1_backup`（隐藏目录）。不要直接用另一个 MOD 的完整资源大小表覆盖这里。

若有多个启用的 MOD 同时提供这两个路径，需先处理冲突，否则实际生效顺序无法保证。程序只保护你指定的那个目录，不会扫描、停用其他 MOD。现有同名或外部改动会记录/检查；遇到拒绝覆盖提示不要手动强行覆盖。

若提示 `python3` 不存在或找不到资源表，先停止安装并保留提示。不要改 keys、固件、存档，也不要把游戏 XCI 当成 romfs。

## 第一次扫描怎么验收

在存档允许使用 amiibo 的开阔位置，先保存游戏；腾出武器/弓空间。选 amiibo 能力，让落点圆圈出现，加载 `amiibo/rare_hub_archer.bin`。

预期：不下食物、矿石等普通物资；出现核心池中的一件装备。请记下实际奖励以及是否还有普通物资。识别成功不等于 MOD 生效，只有奖励符合才算第一次功能验证通过。

本机暂未完成这一验证，不能保证当前 Suyu 构建无兼容性差异。

## 核心集齐后

完全退出模拟器，用同一安装命令把 `--profile 01_core` 改为 `--profile 02_collection`：后续池含 27 项，包括其他特色武器盾牌、五套勇者装、希克面罩、四神兽头盔、旅人马具。

收藏完成后改为 `--profile 03_refill`：只出 8 种特色武器/弓/盾，核心三件仍权重最高。此版本不会读取背包判断武器是否损坏，可能重复给仍持有的武器。

**这三个配置不会在游戏内自动切换。** 如果要严格排除拿过的每一件，使用父目录的 `owned` 清单工具重新生成剩余池（见开发说明）；它也是人工记录，不会偷偷修改或扫描存档。

## 特殊召唤

- `amiibo/summon_epona_tp.bin`：暮光公主林克身份，用于尝试原版伊波娜首次召唤；后续扫描可能走原有普通掉落，不属于本珍品入口。不是每次都保证出马。
- `amiibo/summon_wolf_link.bin`：狼林克身份，保留独立召唤。没有设置20心或写入实体卡存档区，心数与可用性需当前模拟器实测。

这两份是与之前样本同格式的合成模拟器测试文件，并非实体 NFC 标签备份。三份文件仅通过结构验证，新的召唤身份尚未实机测试。**本 MOD 不把马和狼装进随机宝箱，也不修改其他 amiibo 的掉落。**

## 恢复原状

退出模拟器后运行：

```sh
python3 /home/deck/Documents/DECK_TRANSFER/install.py --romfs "你的实际路径/romfs" --restore --apply
```

恢复最初备份的两个路径；如果原来没有008文件，则仅删除本工具新增的008文件。备份继续保留。若安装后你又用其他工具修改过这两个文件，恢复会拒绝覆盖，需要先人工核对。
